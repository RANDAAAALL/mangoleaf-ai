## How to read saved artifacts

An **artifact** is a saved record, such as a JSON plan or CSV prediction table. A **figure** is a visual explanation made from records or images. Both need run identity and provenance before they become evidence.

The table explains which records the notebooks produce. Selected V4.1.1 records now live in this guide's `artifacts/` folder; full original runs remain in the external archive. The curated files were checked against their original hashes. Do not substitute V4.1 files under V4.1.1 names.

| Planned V4.1.1 artifact                                                                                | Made during                 | What it tells you; how to read it                                                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------ | --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `input_manifest.json`, `dataset_split.zip`, `duplicate_audit.json`                                     | Training input audit        | Exact image identities, split membership, and similarity flags. A flag needs visual review; it is not an automatic wrong-label finding.                                                             |
| `white_background_review.json`, `mask_review.json`, `lighting_review.json`, `background_schedule.json` | Human input review          | Which originals may receive scenes, which masks preserve the mango part, what local light looks like, and which scene is scheduled. Compare with V4.1 to identify any actual recipe change.                                                                          |
| `arms/<arm>/training_history.json`, saved model and `resume_info.json`                                 | Each arm's training         | Per-epoch train/validation loss and accuracy, checkpoint choice, temperature, and model identity. Curves do not prove field accuracy.                                                               |
| `training_complete.json` and its model hashes                                                          | Training export             | Confirms all four arms and saved exports belong to the same run. ## Comparison boundary

Same source files, split, scene pool, review decisions, augmentation settings, model architecture, 5 + 10 epoch schedule, calibration, and threshold-selection rule make this a **V4.1 recipe reproduction**. New training still makes new weights and requires its own fitted thresholds. Colab GPU, library versions, and random execution can change results even with seed 42; **identical V4.1 percentages are not guaranteed**. Record actual differences instead of changing the workflow to chase a number.

Fixing missed white-background selections, removing unsuitable scenes, adding training mango images, changing labels, or refitting with different OOD photos is scientifically valuable but changes the recipe or selection. Record that as a new corrected experiment, such as V4.2. The reused mango test, old OOD report, and 32-photo V4.1 OOD set support exploratory reproduction only. Before claiming improvement, evaluate frozen choices on truly untouched OOD photos and expert-labeled mango field photos, then complete application and physical-device checks if a model is considered for adoption.
